================================================================================
 WHAT THIS VERIFICATION FOUND - CRFD-117b
================================================================================

 The first candidate - the tree that was tagged v1.0.0 before this run - passed
 all three gates too. What the smoke test *printed* is what gave it away:

    PASS  event accepted (id EVT-B1CB5C50-F67)

 docs/05 shows "eventId": "EVT-7F3A91C4", and the same PREFIX- plus eight
 uppercase hex characters is the shape of the ALT- and FB- keys minted for
 alerts and explicit feedback. The generator was

    return "EVT-" + UUID.randomUUID().toString().substring(0, 12).toUpperCase();

 and a UUID's first hyphen sits at index 8, so a twelve-character slice keeps
 it. The key had the shape of a truncated UUID rather than of a business key.

 No test noticed, because every test asserted the wrong thing: that the stored
 event could be found, or that the key starts with "EVT-". Nothing pinned the
 shape - the same gap that let CRFD-117 through in the first place.

 The contract test was written first, and observed failing against the tree
 that had already been tagged:

   $ .\mvnw -B -o test -Dtest=EventServiceTest

   [ERROR] Tests run: 6, Failures: 1, Errors: 0, Skipped: 0
   [ERROR] com.crfd.dashboard.service.EventServiceTest
           .mintsBusinessKeyInTheDocumentedShape -- Time elapsed: 0.111 s
     expected: "EVT-[0-9A-F]{8}"
      but was: "EVT-B81AF717-948"
   [ERROR]   EventServiceTest.mintsBusinessKeyInTheDocumentedShape:90
   [INFO] BUILD FAILURE

 The generator now strips the hyphens before truncating, so the key has the
 documented shape at any length, and the test additionally asserts that the key
 the client is handed is the key the pipeline is scheduled with. The suite went
 from 31 tests to 32, which is why the counts that describe the shipped suite
 read 32 while the transcript below still reads 31.

 Because this was found by *release* verification rather than by a test, the
 repair is committed on the release branch, which is what the release branch is
 for, and the tag was re-cut afterwards.

 process can and cannot promise.
